# Harmony 5.0 — design exploration

Two competing proposals for a global design refresh of @gigadrive/harmony and the
Gigadrive apps, prototyped as static HTML compiled against harmony's real Tailwind
config + `index.css`, screenshotted with headless Chrome.

Shared ground in BOTH proposals (direction-independent fixes):

- Brand green `#16A34A` (hsl 142.13 76.22% 36.27%) stays as `--primary` in both modes;
  only the stock-shadcn pink-tinted `--primary-foreground` becomes pure white.
- Real semantic status tokens (`success/warning/danger/info` + soft variants) — fixes
  the broken `success: 'colors.emerald'` string literals in all tailwind configs.
- Layered surfaces: `card` ≠ `background` in dark mode; sidebar tokens de-shadcn'd.
- Dot-style StatusBadge, top-label Input (replaces broken floating label), CardTitle
  at text-base, dense table variant, mono IDs + tabular numerals, SettingsCard v2
  with field rows + status-aware save bar, Button `loading` prop, segmented control.
- Console mocks replicate the real shell: inset sidebar variant, breadcrumb
  org ▸ app ▸ env selectors, right utility rail, no visible page h1.

## Proposal A — "Precision" (flat, hairline)

`theme-proposed.css` (scope class `.p2`). Files: `sheet-proposed.png`,
`console-proposed-{light,dark}.png`, `settings-proposed-dark.png`.

- Flat buttons (gloss removed), font-medium, h-9/h-8 sizing.
- Depth from surface lightness steps + hairline borders; shadows minimal.
- Underline tabs; flat dot chips; radius tightened to 0.5rem.
- Very dark canvas (bg 4.7%), Vercel/Linear-like operational calm.

## Proposal B — "Tactile" (gloss-forward)

`theme-b.css` (scope class `.pb`). Files: `sheet-b.png`,
`console-b-{light,dark}.png`, `settings-b-dark.png`.

Keeps the current glossy button finish and extends its dimensional language so it no
longer sits alone:

- Raised = glossy: buttons (current recipe kept, deeper drop shadow in dark), active
  segmented-control thumbs, status chips, switch knobs, progress fills (`.fill-gloss`).
- Sunken = recessed: inputs, segmented tracks, progress tracks get inner shadows (`.well`).
- Cards: gradient sheen + inset top highlight + layered soft shadow (`.card-tactile`).
- Dark surfaces lifted (bg 6.7%, card 10%) so shadows/highlights have room to read;
  light canvas gets a soft green-gray tint so white cards pop.
- Radius stays generous (0.75rem); segmented tabs instead of underline tabs.

## Comparison notes

|             | A — Precision                    | B — Tactile                                              |
| ----------- | -------------------------------- | -------------------------------------------------------- |
| Buttons     | flat + border                    | current gloss, kept                                      |
| Depth model | lightness steps + hairlines      | shadow + highlight + recess                              |
| Tabs        | underline                        | segmented, raised thumb                                  |
| Dark bg     | 4.7% (near-black)                | 6.7% (lifted for shadows)                                |
| Radius      | 0.5rem                           | 0.75rem                                                  |
| Feel        | Vercel/Linear, dense ops         | Raycast/Stripe, tactile product                          |
| Risk        | gloss removal changes brand feel | gloss must be applied consistently or it looks half-done |

Composites: `compare-console-dark.png`, `compare-console-light.png`,
`compare-settings.png` (current vs A vs B), plus `compare.html?set=sheets`.

## Regenerate

```bash
cd packages/harmony
./node_modules/.bin/tailwindcss -c tailwind.config.ts -i demo/input.css -o demo/demo.css --content 'demo/*.html'
cd demo
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu \
  --screenshot=console-b-dark.png --window-size=1440,900 --hide-scrollbars \
  --virtual-time-budget=10000 "file://$PWD/console-b.html?dark"
```

Demo-only gotchas (real apps are unaffected): compile against `src/index.css` (its
`* { border-color: hsl(var(--border)) }` rule is required — `theme.css` alone yields
gray-200 borders), and set `color-scheme: dark` in dark mode (next-themes'
`enableColorScheme` does this in the apps).
